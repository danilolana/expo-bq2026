SYS.01

Visão técnica

Desafio BQ é uma aplicação web de página única para a Expô Bentinho 2026. A experiência combina um minigame em Canvas, com controle clássico ou facial, e um quiz de cinco perguntas com dicas conquistadas no jogo.

O navegador mantém todo o estado. Não há roteador, API própria, autenticação, banco de dados ou placar remoto. O componente App.tsx funciona como máquina de estados e troca as telas por renderização condicional.

09estados de tela
70perguntas validadas

Responsabilidade central. App.tsx coordena progressão, pontuação, dicas, timers e ciclo do rastreador. Regras puras ficam nos motores de quiz, colisão, dificuldade e calibração, o que permite testes determinísticos.

ENG.01

Como cada mecânica funciona

Preloader

App começa em loading e agenda a introdução com setTimeout(..., 1050). O timer é cancelado no unmount. Não mede o carregamento real dos assets.

Minigame

GameEngine executa um loop com requestAnimationFrame. O delta de cada quadro é limitado a 50 ms para evitar saltos grandes após travamentos ou troca de aba.

  • Área lógica fixa de 960 × 540, adaptada visualmente por CSS.
  • Dificuldade sobe em 10 s e 20 s: velocidade aumenta; abertura e intervalo diminuem.
  • Objetos saem pela esquerda e são removidos para controlar memória.
  • A rodada termina por tempo, ao coletar 3 dicas ou no 3º impacto.
  • Após impacto, há 1,05 s de invulnerabilidade e feedback visual.
Controle clássico

ClassicController aplica gravidade de 980 px/s² e impulso vertical de -305 em pointerdown ou Espaço. A velocidade máxima de queda é 520; limites verticais amortecem o movimento.

Controle facial

FaceTracker solicita a câmera frontal em 640 × 480, tenta inicializar o Face Landmarker em GPU e recua para CPU. A leitura ocorre a cada 40 ms e usa o landmark 1, coordenada y do nariz.

  • A calibração exige pelo menos 12 leituras, cerca de 1,7 s de histórico e variação máxima de 0,018.
  • Uma zona morta de 0,012 reduz tremores; deslocamentos são normalizados em ±0,16.
  • O alvo fica entre 58 px e 482 px e recebe suavização exponencial.
  • Sem rosto detectado, o último alvo válido é mantido.
Colisão e coleta

Obstáculos usam interseção retângulo-retângulo; dicas circulares usam o ponto do retângulo mais próximo do círculo. A hitbox do pássaro é menor que o desenho para tornar o controle mais tolerante.

Sorteio do quiz

createQuizRound filtra IDs inválidos, remove perguntas já usadas e garante cinco itens com ao menos uma pergunta de informática. O algoritmo reserva perguntas técnicas suficientes para as rodadas restantes. Após 70 perguntas, inicia novo ciclo.

Persistência

Somente IDs usados são gravados em localStorage, na chave desafio-bq:used-question-ids:v1. JSON inválido ou acesso bloqueado resulta em lista vazia; o jogo continua na sessão.

Dicas

Cada coletável vira uma dica disponível. Uma dica só pode ser gasta antes de responder e uma única vez por pergunta. Ao avançar, a pista é ocultada, mas o saldo restante é preservado.

Resposta e pontuação

O primeiro clique bloqueia todas as alternativas, incrementa o placar quando correto e revela a resposta válida. Após 650 ms, avança ou abre o resultado. O resultado calcula Math.round(score / 5 * 100).

Inconsistência conhecida. GameIntro.tsx afirma “As colisões não encerram o jogo”, porém gameEngine.ts encerra no terceiro impacto e os testes confirmam essa regra. Até o texto ou o motor ser corrigido, considere o comportamento do motor como fonte operacional.

OPS.01

Iniciar localmente

Confira o ambiente

Use Node.js 20.19 ou superior; a linha 21 não satisfaz a faixa declarada pelo Vite 8. Recomendado: uma versão LTS compatível e npm.

node --version
npm --version

Instale exatamente o lockfile

npm ci limpa e recria node_modules conforme o lockfile. Use npm install apenas ao atualizar dependências.

npm ci

Suba o servidor

npm run dev

Abra a URL informada pelo Vite, normalmente http://localhost:5173. A câmera funciona em localhost; em outro host, use HTTPS.

Valide antes de entregar

npm test
npm run build
npm run dev -- --host 0.0.0.0

O último comando é opcional e expõe o servidor à rede local; confirme firewall e não o use como servidor de produção.

DEV.01

Exemplos relevantes

Adicionar pergunta

Respeite o contrato e a validação global

{
  id: 'tech-26',                // Deve ser único.
  category: 'informatica',        // 'informatica' ou 'geral'.
  prompt: 'Texto da pergunta',
  options: ['A', 'B', 'C', 'D'], // Exatamente quatro.
  correctAnswer: 0,               // Índice entre 0 e 3.
  hint: 'Uma pista curta.',
}

A validação atual exige exatamente 70 itens, sendo 25 de informática e 45 gerais. Ao adicionar uma pergunta, remova ou reclassifique outra, ou altere conscientemente validateQuestionBank e os testes.

Integração

Criar uma rodada com tratamento de falha

try {
  const usedIds = loadUsedQuestionIds()
  const nextRound = createQuizRound(questionBank, usedIds)
  saveUsedQuestionIds(nextRound.usedIds)
  setRound(nextRound.questions)
} catch (error) {
  console.error(error) // Diagnóstico técnico.
  setError('Não foi possível preparar a rodada.') // Mensagem segura.
}

Para trocar o array local por uma API, transforme a resposta em Question[], valide o formato e as contagens antes de chamar o motor, trate timeout/status HTTP e preserve uma mensagem de recuperação na interface.

Ciclo de vida

Sempre libere câmera e listeners

useEffect(() => () => {
  window.clearTimeout(transitionTimer.current)
  trackerRef.current?.stop() // Para tracks, timer, vídeos e modelo.
}, [])

FaceTracker.stop() interrompe tracks do MediaStream, limpa a assinatura, desconecta vídeos e fecha o landmarker. Esse cleanup evita câmera ativa após sair do fluxo.

Teste determinístico

Injete uma fonte aleatória controlada

const round = createQuizRound(
  questions,
  previouslyUsedIds,
  seededRandom(123456), // Repete a mesma sequência.
)

expect(round.questions).toHaveLength(5)
expect(round.questions.some(q => q.category === 'informatica')).toBe(true)

O terceiro parâmetro de createQuizRound existe justamente para testar sorteios sem flutuação.

QA.01

Qualidade e verificação

4 arquivos aprovados15 testes aprovadosbuild aprovado31/08/2026

Na auditoria, npm test concluiu 15 testes em 4 arquivos e npm run build compilou TypeScript e gerou o bundle Vite. Os testes cobrem:

  • contagem, categorias, IDs e respostas do banco;
  • 14 rodadas sem repetição e reinício do ciclo;
  • duração, limite de dicas e encerramento por impactos;
  • calibração e limites do mapeamento facial;
  • preloader, modo clássico, fallback da câmera, consumo de dicas e conclusão do quiz.

Smoke test manual

  • Execute o fluxo completo em 360 × 800, 844 × 390, 768 × 1024 e 1440 × 900.
  • Teste Tab, Enter, Espaço, toque e clique; confirme foco visível e ausência de rolagem horizontal.
  • Negue a câmera e verifique o fallback; depois autorize em Chrome/Edge e valide GPU/CPU.
  • Ative “reduzir movimento”, zoom de 200% e rotação retrato/paisagem.
  • Limpe e corrompa a chave do localStorage; o quiz deve continuar.
  • Bloqueie jsDelivr/Google Storage; o modo câmera deve falhar com mensagem e o clássico deve funcionar.
SEC.01

Erros, privacidade e segurança

Privacidade da câmera

Quadros são processados no dispositivo e não são armazenados pelo código. Tracks são encerrados ao sair. A interface informa esse uso.

Fallback progressivo

Erros de permissão, ausência, câmera ocupada, navegador incompatível e modelo indisponível recebem mensagens específicas e acesso ao modo clássico.

Dados locais mínimos

O armazenamento contém apenas IDs de perguntas. Leitura e escrita ficam em try/catch, sem dados pessoais ou respostas do jogador.

Cadeia de fornecimento

WASM e modelo facial são baixados de terceiros em runtime. Produção deve definir CSP, fixar origens, monitorar disponibilidade e considerar hospedar os arquivos localmente.

Sem camada de confiança

Placar e progresso vivem no cliente e podem ser alterados pelo usuário. Não use esses dados para prêmio, ranking ou decisão sensível sem backend autoritativo.

Acessibilidade

Botões nativos, estados aria-live, mensagens com role, foco e prefers-reduced-motion apoiam navegação assistiva. Canvas possui rótulo textual, não equivalência completa.

REF.01

Premissas, limites e manutenção

Premissa

Navegador moderno

ES2022, módulos, Canvas 2D, requestAnimationFrame e APIs de mídia devem estar disponíveis.

Limite

Sem backend

Não existem contas, sincronização entre dispositivos, analytics próprio, ranking ou persistência remota.

Limite

Histórico local

Limpar dados do site ou trocar de navegador reinicia o ciclo das 70 perguntas.

Premissa

Uma face

O landmarker está configurado com numFaces: 1; iluminação e enquadramento afetam a leitura.

Manutenção

Dependências

Substitua latest por faixas explícitas se quiser upgrades controlados. Revise lockfile, testes e bundle em cada atualização.

Manutenção

Conteúdo

Qualquer mudança na proporção 25/45 ou total 70 exige atualizar validação, motor se necessário, testes e esta documentação.

Critério de entrega. Uma alteração está pronta quando TypeScript compila, os 15 testes existentes continuam verdes, novos ramos ganham cobertura proporcional e o fluxo crítico passa no smoke test de desktop, mobile e fallback sem câmera.
